# Layer 13: Frontend Clarity, Dashboard Analytics, and Multi-Object 3D Visualization

## 1. Overview and Objectives

Layer 13 enhances the usability, visual polish, and scientific communication of the ADITI 4.0 Space Situational Awareness (SSA) platform without rebuilding the frontend from scratch or altering underlying astrodynamic calculations.

Key objectives achieved:
1. **Dashboard Usability & Indefinite Spinner Fix**: Diagnosed and resolved the root cause of prolonged spinners on initial page mount. Added client-side request timeout abort controllers, fast baseline threat screening, and comprehensive empty/loading/error states.
2. **Dashboard Overview & Analytics**: Integrated catalogue-wide altitude distribution (LEO, MEO, GEO, HEO) stacked bar charts, provenance cards, and top priority threat summaries directly into the dashboard.
3. **Satellite Explorer Parameter Clarity**: Transformed raw Keplerian numbers into an understandable, scientific orbital profile with units, interactive parameter guides, altitude profile gauge, and collapsible advanced SGP4 parameters.
4. **Conjunction Analysis Neutrality**: Replaced broken-looking disclaimers with clear, neutral informational guidance. Added miss distance proximity gauges and detailed parameter explanations.
5. **Multi-Object 3D Globe Visualization**: Implemented catalogue-wide bounded SGP4 propagation (`GET /satellites/multi-propagate`) rendering up to 200 satellite markers simultaneously on CesiumJS, complete with regime filtering, search, interactive object selection, and trajectory arcs.

## 2. Root Cause Analysis: Dashboard Spinners & Performance Fix

### 2.1 Diagnosis
In previous prototype iterations, the dashboard mounted `ThreatPrioritizationPanel`, which triggered an unprompted, heavy screening request on page load:
- Defaulting to 5 protected targets × 20 threat candidates over 48 hours with 120s coarse step.
- Required 100 orbital pair evaluations × 1,440 SGP4 steps = 144,000 propagation computations synchronously in Python.
- Execution time was ~33 seconds on local CPU.
- During these 33 seconds, concurrent API calls (e.g. `/catalog/status`, `/satellites?limit=5`) queued up behind the CPU-bound operation.
- Additionally, `frontend/src/api/client.ts` had no fetch timeout, meaning any stalled or slow request left an indefinite loading spinner in the browser.

### 2.2 Fix
1. **Client-Side Timeout Safeguard**: Added an `AbortController` timeout (30 seconds) in `apiFetch`. If the backend takes longer than 30s, the request cleanly aborts with HTTP 408 and displays an actionable error and retry button rather than hanging.
2. **Fast Baseline Mount Screening**: Default initial mount screening in `ThreatPrioritizationPanel` is tuned for instant feedback (2 targets × 4 candidates, 12h window), executing in ~0.4 seconds. Users can execute full custom screening runs on demand via the "Run Threat Screening" button.
3. **Comprehensive State Handling**: Ensured all components transition unambiguously from `loading` to `data` or `error` with retry controls.

## 4. Satellite Explorer: Understandable Orbital Parameters

The `SatelliteInfo` component now translates raw orbital elements into clear, accessible physics:

| Parameter | Unit | Display & Description |
| :--- | :--- | :--- |
| **Mean Altitude** | km | Computed from semi-major axis: $a = (\mu / n^2)^{1/3} - R_{\text{Earth}}$. Displays perigee and apogee bounds. |
| **Orbital Period** | minutes | Computed as $1440 / n$. |
| **Inclination** | degrees (°) | Orbital tilt relative to equator, categorized as Equatorial, Inclined, or Polar. |
| **Eccentricity** | dimensionless | Geometric shape: classified as Circular ($e < 0.005$) or Elliptical. |
| **Epoch Age** | days | Time elapsed since observation epoch. Flagged with warning if $> 14$ days. |
| **RAAN ($\Omega$)** | degrees (°) | Right Ascension of Ascending Node — orientation of the orbital plane in space. |
| **Argument of Perigee ($\omega$)** | degrees (°) | Angle from ascending node to closest approach point (perigee). |
| **Mean Anomaly ($M$)** | degrees (°) | Angular position along orbit relative to perigee at epoch. |
| **BSTAR** | $1 / R_{\text{Earth}}$ | SGP4 atmospheric drag term parameterizing ballistic decay. Not a direct drag force measurement. |

### Visual Elements Added:
- **Orbital Regime Gauge**: Visual bar indicating the object's altitude relative to LEO boundary (2,000 km) and Geostationary belt (35,786 km).
- **Interactive Information Buttons**: Hover/click explanations explaining every technical parameter.

## 5. Conjunction Analysis: Clearer Advisory Wording

### 5.1 Neutral Disclaimer
Replaced alarming error-styled warnings with neutral informational guidance:
> *“Research prototype using public orbital data. Results are advisory and are not operational collision-avoidance guidance.”*

### 5.2 Clarified Terminology
- **Miss Distance**: Predicted minimum geometric separation between the two propagated objects.
- **Relative Speed**: Relative velocity magnitude at closest approach.
- **Time of Closest Approach (TCA)**: UTC epoch when minimum separation is achieved.
- **Separation Proximity Gauge**: Visual bar comparing miss distance against the user-configured encounter threshold.

## 6. 3D Globe Multi-Object Visualization Architecture

### 6.1 Backend Endpoint: `GET /satellites/multi-propagate`
Exposed bounded multi-object propagation via `backend/api/routes.py`:
- **Query Parameters**:
  - `limit`: [1, 200] (default: 50).
  - `offset`: pagination offset.
  - `target_time`: target UTC timestamp (default: now).
  - `category`: classification filter (`ACTIVE_SATELLITE`, etc.).
  - `regime`: orbital regime filter (`LEO`, `MEO`, `GEO`, `OTHER`).
  - `search`: case-insensitive substring search in object name or NORAD ID.
  - `norad_ids`: comma-separated explicit NORAD IDs to propagate.
- **Returns**: `MultiPropagatedOrbitResponse` containing array of `MultiPropagatedObjectState` with TEME coordinates $[X, Y, Z]$, altitude, velocity, and SGP4 status.

### 6.2 Frontend CesiumJS Integration
- **TEME-to-Fixed Transformation**: Converts TEME coordinates to Cesium's pseudo-fixed frame via `Transforms.computeTemeToPseudoFixedMatrix(JulianDate.fromIso8601(timestamp))`.
- **Performance Bounds**: Renders between 25 and 200 objects simultaneously without UI stutter or memory leaks.
- **Color Coding**: Cyan for LEO, blue for MEO, emerald for GEO, amber for selected or stale objects.
- **Interactive Picking**: Clicking any satellite point on the 3D globe selects the object, displays its telemetry panel, and allows one-click propagation of a 90-minute trajectory arc.
